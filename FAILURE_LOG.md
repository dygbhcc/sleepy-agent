# Failure log

Every day something breaks. This file keeps the evidence: what I expected,
what happened, why, and what I changed. Entries include mistakes caused by my
own tests and assumptions, because those are the most useful ones.

| Day | What broke | Cause | Fix |
| --- | --- | --- | --- |
| D2 | `gofmt` rejected my first `Mock` struct (field alignment) | I wrote it by hand and never ran the formatter | `make lint` now fails on unformatted code, and CI runs it |
| D2 | The naive pipeline accepts a 5 word script and a script that repeats one sentence 60 times (pinned by `TestKnownGap*`) | No QA gate exists yet. In Sleepy these were the first real failures, found only by reading the output | Planned for D7: QA gates, and those tests flip to expect a rejection |
| D3 | First real call to Groq returned HTTP 404: the hardcoded default model `llama-3.3-70b-versatile` was not available to my key | Model names change and I baked one into the provider. Mocks and `httptest` could not catch it | Removed the default model, `GROQ_MODEL` is now required with a key |
| D3 | `openai/gpt-oss-20b` and `openai/gpt-oss-120b` both returned HTTP 400 "Tool choice is none, but model called a tool" on the first call, 0 tool calls completed | The gpt-oss models are trained for native tool calling. They try a native call when my prompt lists tools in text, and the request carries no `tools`. My first fix (JSON mode) did not help: same error on both sizes | Not fixed in the protocol. `qwen/qwen3.8-27b` completed the same task: 3 tool calls, 1445 prompt and 203 completion tokens. Native `tools` support was added on Day 4 as a second adapter (`llm.PromptTools` is the first). Measured with `make compare`, 5 runs per mode: both gpt-oss sizes completed 5/5 with native tools and 0/5 with the prompt protocol (20b: five HTTP 400 "Tool choice is none"; 120b: three of those plus two HTTP 400 "Failed to validate JSON"). Qwen completed 5/5 in both modes |
| D4 | `Worker.Drain` never returned when I broke the store on purpose so it handed back a run that was waiting for approval: the test run died after 78 seconds, and a rerun was still looping after 2 minutes | `Drain` trusted the store to make progress. Found by a mutation check of my own tests, not in normal use | `Drain` now stops with an error after `MaxDrainSteps`, with a test that uses a store that forgets approvals |
| D4 | My first native tool calling test failed with `invalid arguments for get_policy: argument "duration_minutes" must be of type integer, got int` | I scripted the mock with a Go `int`. Real providers send JSON, which decodes numbers as `float64`, and the validator was right to reject it | The mock now uses `float64`, like a real reply |
| D4 | First `make compare` on `qwen/qwen3.8-27b`: 5 of 5 native runs and 1 of 5 prompt runs ended as HTTP 429 rate limit errors, so the table compared my request rate, not the two adapters | The harness fired runs back to back and treated a rate limit as a model failure | `compare` now pauses between runs, waits out transient errors up to 3 times and counts every retry in its own column |
